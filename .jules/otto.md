# Otto's Journal — Reusable Backlog & Project Learnings 🦦

## 2026-09-03 - GitHub Project Schema Invariants **Learning:** FullStackTemplate uses Notoli's Project schema baseline defined in `scripts/create-github-project.ps1` and `docs/GITHUB_SETUP.md`. Valid Project fields and allowed values are: Status (`Backlog`, `Ready`, `In Progress`, `In Review`, `Done`), Domain (`Frontend`, `Backend`, `UX/UI`, `Data Model`, `Deployment`, `CI/CD`), Type (`Bug`, `Feature`, `Enhancement`, `Refactor`, `Chore`, `Research`, `Security`), Priority (`P0`, `P1`, `P2`, `P3`), and Size (`XS`, `S`, `M`, `L`, `XL`). **Action:** Always validate Project metadata against these exact options without inventing custom fields or status values.

## 2026-09-03 - Active Implementation Protection **Learning:** In-flight specialist PRs (such as Marty's repository health PRs #112, #109, #106, #103, Nora's component extraction PR #108, or Forge's auth session PR #98) represent active implementation work whose scope and acceptance criteria must not be rearranged mid-flight. **Action:** Treat issues and PRs with active specialist implementation as protected active work, ensuring their Project status reflects review/progress accurately without altering their scope.

## 2026-09-03 - Automated Security Alert Issues **Learning:** Security alert issues (e.g., #80, #81, #82) are managed directly by `.github/actions/security-alerts/sync-security-alerts.js`. **Action:** Do not manually alter source alert comments or issue bodies on alert issues; let the automated security workflow reconcile them based on source alert state.
